## 实施边界

本轮已落实可收起工具、独立规则、结构化编辑、放置校验预览、发展计划与阻碍、自主外交／迁徙／分裂及事件详情。2026-10-02 接续实现补齐相似事件聚合、可验证的事件因果、有限占领与防御目标、实际经历时间线、跨对象统一关注及有稳定工作样本的完工预估。战争范围由同步问答明确限定为有限占领与防御；家族继承、掠夺和全面征服尚未实现。因果关联只覆盖具有真实依据的路径，不为所有事件猜测前因；实际边界与工程默认值见现行产品文档。

## 已确认的方向

1. 最初先讨论方案，随后用户明确要求“修改并部署”，已转入实施。
2. 核心乐趣是文明自主演化、兴衰、冲突和人物故事，玩家观察并干预。
3. 正常速度下，期望约 1–3 分钟有值得关注的变化，10–20 分钟能看到一段文明发展。
4. 支持自主贸易、结盟、战争、停战、迁徙与分裂；默认强度适中，留出恢复时间，规则可分别调节。
5. 地图放置建筑默认由上帝直接赐予，也能切换为消耗当地资源、由居民施工的建设项目。
6. 清理工具与窗口入口，允许关闭工具和选择区域；提高移动端有效地图面积；删除地图左上角常驻世界介绍。
7. 产生机制影响的编辑采用有约束的结构化输入，清楚解释效果；按钮图标不使用字体符号。

以下具体机制、控件、默认值与实施顺序均为建议，尚未逐项确认。它们不覆盖模拟的本地认知、实地劳动与通信、只读观察以及可靠存档要求。

## 一、核心玩法：发展、关系与干预形成连续后果

建议的玩家循环：看见一个变化或矛盾 → 理解原因与可能走向 → 决定旁观或干预 → 看到即时结果和后续影响 → 继续追踪这个文明或人物。

### 1. 文明要有当前打算和可观察的成长

每个聚落保留明确的发展打算，例如稳定粮食、扩充住房、修建学院、研究运输、建立新聚落。根据当地需求、已知条件与制度调整优先级，并保留实际采用的理由。资源不足时可转向采集、调整岗位、求援或交易；不能反复尝试同一个无法完成的建筑，也不能凭空补资源。

聚落摘要固定显示：当前打算、实际进度、主要阻碍、近期变化。比如“修建学院：施工 42%；缺少到场工人”，并能定位工地与承担任务的居民。完成时间只在确有稳定工作速率时估计，停工时明确显示原因。

文明阶段从实际成果归纳：稳定定居、形成余粮、专业分工、建立区域网络等。阶段应对应建筑形态、人口分布、生产能力、贸易流量或通信能力的变化，不把国家的等级字段直接当作完整科技树。

### 2. 文明之间形成关系变化

首先建立贯通的“接触—往来—关系变化—合作或冲突—恢复”过程：

- 资源互补与可达路径产生贸易、援助和合作需求。
- 边境接触、资源竞争、冲突经历影响关系；和平相处和互惠也产生正向变化。
- 机构依据实际收到的信息，决定结盟、施压、开战或停战；保留原因及来源。
- 战争有目标、补给约束、撤退与停战条件；战损、资源负担和局势变化让文明有恢复阶段。
- 迁徙、分裂与重建作为完整兴衰的后续环节，受生存条件、文化差异、治理与消息传递影响。

默认强度通过条件阈值、冷却和恢复机制调节。1–3 分钟是典型世界的体验目标，不是到点强制开战或生成灾难。没有接触条件的孤岛也应能通过本地发展产生看点。

### 3. 玩家干预要留下可追踪的结果

例如：干旱造成粮食下降 → 聚落调整劳动并请求援助 → 邻国回应影响关系 → 玩家疏通道路 → 运输抵达、短缺缓解 → 合作关系延续。战争只是其中一种走向。

事件详情关联真实的前因、参与者、地点与已发生后果；未来分支标为可能性。不能在玩家铺路后立即宣布粮荒解决，必须等实物运输产生效果。

允许关注国家、聚落或居民，汇集其关键转折。第一阶段先利用真实经历、决策和已有事件组织人物故事，再评估家族、继承等新体系。

### 4. 看点直接出现在地图上

- 使用简短事件条展示首次研究、重要建设、扩张、关系转折和危机，点击定位并展开原因。
- 相似高频事件合并；按“首次、显著变化、与关注对象相关”提升优先级，避免全部日志都变成通知。
- 不自动弹窗或抢镜头；追踪镜头由玩家明确开启，可随时退出。
- 危机和发展都有地图表现：工地、实际往来、扩展聚落、灾区与军队动态。
- 空闲时可提供“关注一个文明”等可关闭提示，不要求玩家完成任务清单。

## 二、交互架构：地图工具、观察与设置有清楚边界

| 区域 | 职责与建议行为 |
| --- | --- |
| 精简顶栏 | 时间、人口、暂停/倍率和菜单；规则、新世界与存档从菜单进入 |
| 地图工具 | 地形、生命、建筑、道路、灾害、领土等直接作用于地图的动作 |
| 观察入口 | 点击对象查看详情；另设居民/国家目录、事件列表 |
| 地图图层 | 国界、资源、交通、通信覆盖；每个选项说明它回答的问题 |
| 对象详情 | 当前对象、状态、打算、原因和编辑入口；有路径、返回、定位与关闭 |
| 世界规则 | 独立设置窗口，分组、预设、影响说明和应用按钮 |

分类切换只展开工具选项，不自动激活第一项或打开窗口。当前工具、当前选择对象和当前页面分别显示，避免共用一个含糊的高亮。

观察按玩家的问题组织：对象详情回答“它现在怎么样、为什么”；事件回答“发生了什么”；地图图层回答“哪里有问题”。物流属于聚落的生产与运输信息；通信图层显示覆盖，通信详情展示消息来源与时效，减少重复的平级入口。

暂存查看路径，例如“国家 → 聚落 → 学院”。从居民跳到聚落后可返回原居民及原滚动位置；世界刷新不打断输入和导航。

## 三、工具操作与放置反馈

### 工具状态

明确区分漫游、工具待用、预览与执行。再次点当前工具可停用；收起整个工具抽屉时暂停地图操作并恢复漫游，保留上次选择供显式恢复。切换分类不改变地图。

桌面保留右键/中键漫游；触屏默认单指拖动平移、双指缩放。手机上建筑、投放与灾害采用“点选位置预览 → 确认”的操作；拖动调整镜头不执行放置。地形轻点盖章，连续绘制可通过明确的绘制开关进入，并保留双指漫游。

Escape 优先取消当前预览，再关闭最上层界面，最后退出地图工具；不会一次关闭多层而使玩家迷失。时间控制保持独立，保留空格暂停语义。

### 工具参数与预览

| 工具 | 参数和预览 |
| --- | --- |
| 地形/领土 | 笔刷范围，显示实际覆盖地格 |
| 道路 | 线段或路径预览，显示受阻路段与费用；不默认当作大面积圆刷 |
| 建筑 | 建筑轮廓、归属、赐予/施工模式、运营前提；施工模式另显示资源差额 |
| 生命 | 种族与数量，预览落点与可落地范围 |
| 灾害 | 单次释放，使用强度与作用范围参数，显示预计受影响区域 |

预览以颜色加轮廓/图标表达可放置、不可放置和有条件可用。提示贴近预览或触屏确认栏，具体说明“距聚落太远”“木材缺 8”“已有建筑”等；无效操作不扣资源、不改变世界、不创建撤销记录。

赐予建筑建议跳过材料与施工时间，仍校验地形、占位、归属和适用规则。是否具备人员或运营知识单独提示；建筑出现不代表知识被全体居民瞬间掌握。施工模式由当地真实库存与人员推进。两种操作都标记为玩家干预。

选择、查看与预览不改变模拟时间。涉及编辑时明确显示暂停状态及继续入口；“运行中干预后是否自动恢复”作为后续可调交互选项，首版沿用清楚可见的暂停编辑边界。

## 四、移动端布局与信息密度

默认进入观察状态，工具抽屉和详情收起，删除左上角世界介绍卡。世界名称、种子和尺寸放入世界信息页。

建议布局为精简顶栏、主地图、单行底部入口和可展开抽屉。手机同一时刻只展开工具抽屉或对象详情之一；详情采用底部半屏与全屏两档，避免上下两块面板夹住地图。全屏编辑保留明显返回和固定提交区。

紧凑布局从删除重复标题、装饰文案、嵌套卡片和无用空槽开始。参数使用紧凑行，卡片留白减少，但触控命中区保持约 44 CSS 像素，不靠缩小文字和按钮提升密度。核心入口保持位置稳定；抽屉高度可由用户展开改变，不随模拟刷新跳动。

建议验收目标：在 390×844 竖屏、详情和工具收起时，无遮挡地图高度至少占应用可用高度的 75%；展开工具时不同时常驻世界介绍或观察栏。另验证 360 像素宽、横屏、软键盘和屏幕旋转。

按钮使用 Avalonia PathIcon、矢量几何或明确资源，统一尺寸和线宽；保留文字标签、可访问名称与提示。关闭、缩放、播放等操作不依赖字体中的符号形状。

## 五、编辑器：玩家选择想改变的东西

应按字段含义选择控件，并让玩家看懂修改效果：

| 内容 | 控件 |
| --- | --- |
| 姓名、世界/国家名称 | 文本框 |
| 年龄、资源、生命、影响强度 | 有范围、单位、步长的数值输入，适合时配滑块 |
| 种族、职业、制度、目标类型 | 下拉或分段选择，附效果说明 |
| 文化、家园、关系对象、消息来源 | 显示名称的可搜索对象选择器，不要求填写编号 |
| 坐标、目标地点 | 地图选点，数字坐标作为辅助 |
| 规则开关、自治、跟随 | 开关或复选框 |
| 个人经历与记忆 | 类型、对象、时间、强度等结构化字段；可选文字说明 |

例如选择“记忆：某聚落缺粮”，只显示相关聚落、已知粮食量、观察时间、来源与可信度，说明它影响该角色的判断。选择“前往某处”时显示地图选点，不继续暴露不相关的实体字段。

提交前展示直接变更与影响方向：如“勇气 0.3 → 0.7，今后更可能选择冒险行动”。只有能从规则确定的即时变化才给精确值，不承诺复杂模拟必然发生的结果。

自由文字可以保留为名称和可选记述，必须标为不执行的说明。特质应采用与实际性格参数绑定的预设；当前特质名称与性格初始化的关系不能让玩家误以为改一段文字就会重新生成人格。高级 JSON 入口移出普通玩家流程。

## 六、规则体系：丰富可玩的组合

建议提供“和平繁荣”“文明兴衰（默认）”“动荡世界”“自定义”预设。预设只是下表规则值的组合，切换时显示变更。

| 分组 | 建议规则 | 实际作用 |
| --- | --- | --- |
| 人口与生存 | 生育、衰老、饥饿、疾病开关/强度 | 改变人口更新、物资压力与恢复能力 |
| 自主发展 | 自主建设、研究、扩张、发展速率 | 控制文明如何投入、成长与拓展 |
| 社会与外交 | 贸易、结盟、自主战争、停战、迁徙、分裂 | 调整文明之间的关系与格局变化 |
| 环境与灾害 | 火灾/干旱/疫病的频率、强度和传播 | 改变世界压力及恢复窗口 |
| 魔法 | 新发展、训练/恢复速率、能力强度 | 控制魔法成长及其生产、医疗与战争影响 |

界面只展示已经有实际机制的规则；后续机制随实现加入。优先采用关闭/低/标准/高等易理解选项，高级数值再展开。

“时间倍率”加速所有模拟过程；“发展速率”调整建设和研究等过程，含义分开。规则必须存档，恢复后保持一致。

每条规则说明作用对象、生效时机以及对进行中事项的处理。建议关闭“自主战争”只阻止新宣战，已在战争中的国家仍按现有状态行动，可另行停战；关闭新魔法发展保留已有成果。规则禁用关联选项时显示原因，不悄悄改掉其他值。

## 七、实施顺序与验收

### A. 第一批必须同时完成：操作清楚 + 看得见的发展

范围：地图优先布局、工具与窗口分离、工具停用、移动端抽屉、分类参数与放置反馈、常用结构化编辑；发展打算与卡点、自主规划受阻后的合理调整、研究与建设的关键事件提示；建筑赐予/施工切换。

验证：

- 浏览任何工具分类都不打开详情或规则窗口；收起工具后能漫游且不误放置。
- 玩家不用输入实体编号或 JSON，即可完成常见居民、国家和目标编辑。
- 选择聚落能看懂它在推进什么、缺什么；提供所缺条件后，实际施工或研究继续。
- 成长在地图及事件入口可见；首次研究或关键设施完成不会因日志等级被隐藏。
- 建筑预览原因与提交校验一致，失败不修改世界；赐予与施工产生各自约定的结果。
- 达到移动端有效地图面积目标，桌面栏也能真正关闭；用裁剪后 WASM 的真实鼠标/触屏检查验证。

### B. 第二批：形成能持续观察的文明关系

范围：关系形成与原因、自主贸易/合作、结盟、宣战与停战、战争目标和恢复期；关注对象与事件因果；对应世界规则和预设。

验证：

- 在满足接触和资源条件的世界中，无需玩家宣战也能产生有因果依据的外交转折；和平合作同样可见。
- 信息尚未到达的机构不使用远方事实决策，停战消息到达前线前后行为符合通信约束。
- 同一世界改变地理通路或相关规则，能产生可解释的不同后果。
- 对至少五个固定种子，记录正常速度下 20 分钟的发展、停滞、首次突破和关系转折。以 1–3 分钟有看点为调优目标，记录分布和例外，不通过硬插事件达标。

### C. 第三批：丰富完整兴衰与重复游玩

范围：迁徙、分裂、重建、更鲜明的文明发展差异，以及可追踪人物的重要转折；补齐相应规则。

验证：危机具有预兆、实际后果和恢复/分化路径；不同规则组合能形成不同世界走向，且没有某一种默认灾难或冲突稳定清空全部文明的失衡。

所有机制变更执行核心测试、当前格式存档往返与确定续演；涉及 UI 的变更执行发布后子路径浏览器验证。性能、真实设备与主观趣味分别记录；事件变多不能单独证明游戏变有趣。试玩需确认玩家能说出一个正在关注的对象、一个实际因果关系，以及一次干预为何值得进行。
