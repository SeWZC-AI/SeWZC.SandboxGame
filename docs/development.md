# 开发与 AI 协作约定

[产品约定](product.md) 定义行为，[架构说明](architecture.md) 定位状态与模块，[决策记录](decisions/README.md) 解释取舍。构建与测试命令见 [单元测试说明](../tests/README.md)。

## 本地运行

命令均在仓库根目录执行。SDK 版本与回退策略以 [global.json](../global.json) 为准，NuGet 包版本统一维护在 [Directory.Packages.props](../Directory.Packages.props)；Linux 桌面版需要图形会话与系统图形库。

```bash
dotnet run --project src/SeWZC.WorldBox.Desktop
```

浏览器开发服务需要 WebAssembly 工作负载；启动后打开终端显示的本地 HTTP 地址。静态发布与预览见 [部署指南](deployment.md)。

```bash
dotnet workload install wasm-tools
dotnet run --project src/SeWZC.WorldBox.Browser
```

## 修改流程

1. 查看分支与未提交修改，保留他人工作，用 `rg` 定位相关代码和测试。
2. 明确这次改变的玩家行为，区分需求与假设。缺少影响产品方向的信息时使用可用的交互式提问工具，同时继续不依赖答案的工作；已有授权不重复询问。
3. 找到权威状态、命令、观察与保存路径。修改实际机制，并让解释文字反映真实规则。
4. 按改动范围验证；仅在行为、用法或约定变化时更新必要的已有文档，报告完成的检查与未覆盖范围。

小型可逆文案或布局修改不机械加测试；跨状态缺陷优先增加能复现失败的场景，避免复制实现算法。

## 主分支与环境迁移

拉取远端更新使用 `git pull --rebase` 或 `fetch` 后 `rebase`，不创建 merge 提交。`main` 是唯一长期主分支及 Pages 发布分支，alpha 仍是产品阶段。应用版本以 [Directory.Build.props](../Directory.Build.props) 为准。

仓库默认分支、工作流部署条件、`github-pages` 环境分支策略和开发环境检出分支是独立设置；变更后分别核对，修改工作流不会自动同步其余设置。Pages 设置与 CI 范围见 [部署指南](deployment.md#发布到-github-pages)。

## 约束必须有现行依据

- 新增产品、接口或维护约束，须对应已确认需求、实际依赖或可复现缺陷；工程选择写明用途与代价。“以防万一”不能单独成为依据。
- 注释、测试与决策记录不能给自行假设补授权。旧约束与现行需求冲突时，核对并修复实际路径及测试，不补写理由将其固化。
- 删除或替换概念时沿枚举、字段、命令、保存校验、界面和测试检查读写路径。alpha 不为已删除的错误概念保留空编号、废弃字段或迁移层；仍有现行用途的状态不能仅因旧而删除。
- 保存语义改变时同步版本和拒绝旧格式；测试保护现行行为及真实失效边界，不保护某个历史编号。问题或产品取舍不清时澄清，常规实现不增加逐项审批。

## 代码规范

- 类型文件有一个主类型，文件名与其对应；仅文件内或嵌套辅助类型可保留。跨文件使用的类型放同名文件。复杂类型按 `类型名.机制.cs` 分部，在无后缀主文件维护类型注释；实体定义不放进 `WorldEngine.*.cs`。
- 注释用中文。类型注释先说明它是什么，不罗列字段或所有行为；成员说明业务含义、参数约定和必要调用条件，删除重复实现与空泛理由。公开及受保护 API、枚举成员提供 XML 文档；位置式 record 用 `<param>`，接口实现或重写可用 `<inheritdoc />`。参数较多或含义不明确的非公开构造函数同样提供 XML 和参数说明。[构建配置](../Directory.Build.props) 生成 XML，并将 `CS1591` 作为错误。
- 延续人工提交的展开参数、明确类型归属与简洁注释风格，复杂流程不用单字母代替业务含义。枚举 `switch` 分支及同组成员按声明顺序排列；条件重叠、范围匹配和跳转以原匹配语义为先。
- 行为分派优先用带明确参数的对象及多态方法，显示文案和自动化标识不参与业务判断。新地图工具在 `MapTool` 中实现校验、预览和执行，不重新解析 `build:` 字符串。
- 共享规则、费用及前置集合不可变；研究前置直接引用 `Advancement` 对象，前置与解锁保存为 `ImmutableArray`。`ResourceAmounts` 表示只读配方，`ResourceStock` 表示不可变库存值；扣费、缩放和运输显式提交转换后的库存。构造与状态转换优先使用不可变类型，性能取舍先测量、再优化，不以更新频繁为由直接保留可变类型。世界和编辑候选以不可变记录及持久化集合转换；候选校验通过后提交，拒绝操作不污染当前世界。局部可变构建器仅用于日内合并，冻结后交出分支所有权，后续写入重新复制，已返回的世界及实体快照不能被修改。引擎定位引用及派生索引不进入可保存状态。
- 构造后不再赋值的命令参数优先 `init`，必需参数用 `required` 或构造参数；有合法缺省语义的存档字段不能一律改为必需。保留有实际用途的紧凑枚举，热点不增加逐格对象或无依据的通用层。

## 容易破坏的边界

### 模拟与存档

- 核心随机性使用已保存世界随机状态，不引入墙钟、渲染帧率或独立随机源。知识与货物的权威状态见 [架构](architecture.md#状态归属)。
- 消息副本保持来源与观察时间；转移归属使用统一命令。制度读取 `State.Society.Reports`，国家库存只聚合展示。
- 新的因果状态同步处理初始化、序列化、范围及关系校验、中途保存续演。无效编辑或导入先在候选状态拒绝，不污染世界。
- 不全局启用 `WhenWritingDefault`；只有缺失与初始化均明确表示零的字段可省略。种群或覆盖结构新增字段须同步相等、散列与序列化实现。
- 日志按重要性淘汰，新事件可能不被保留。补充元数据用 `AddEvent` 返回值，不能猜测 `State.Events[^1]`。容量调整核对模型、校验器与实际 UTF-8 载荷。

### 界面与缓存

- 周期刷新保留输入、焦点、选择、折叠与滚动；文本比较后再赋值，折叠区不持续重算。功能只描述一次，受阻提示写实际原因、阈值或缺口，字段不用点分隔。
- 对象跳转使用 `OpenResident`、`OpenNation`、`OpenSettlement`、`OpenBuilding`、`OpenTile`，先保存当前位置再改选择。异步提交通过 `SubmitEditAsync` 绑定原世界与界面会话；取点复用 `AddMapPicker`，验证取消、换世界与触屏返回。
- 镜头、路径预览、研究布局与插值只改变呈现。地图图形复用透明像素素材；绘制、命中和跟随使用同一显示位置，高建筑遮挡与屋顶命中共用 `BuildingBounds`。
- 缓存有明确输入和生命周期，不成为世界事实。避免每帧扫描全世界；资源评分或通行规则改变时核对剪枝上界与失效条件。具体缓存责任见 [架构](architecture.md#派生缓存与预算)。
- 浏览器 `text-input.js` 补齐当前 Avalonia 的软键盘路径；升级框架时在真实浏览器检查合成、实体键盘和重复提交，评估是否移除适配。手机尺寸仿真不能证明真机输入法兼容。

## 按改动选择验证

| 范围 | 必要检查 |
| --- | --- |
| 仅文档 | 对照实现、检查相对链接和标题锚点、`git diff --check` |
| 核心行为、数据或编辑 | Release 构建、xUnit 单元测试；针对实际失效边界补最小场景，跨系统行为另行验证 |
| 存档与序列化 | 上述检查，加往返、合法零值、非法输入不改世界；因果状态变化另验中途续演，涉及平台时验真实存储 |
| 界面、输入或呈现 | 相关界面逻辑单元测试；涉及控件或渲染时检查裁剪发布产物的实际桌面／触屏操作及必要的软件回退 |
| 平台入口、资源或部署 | 静态产物与仓库子路径浏览器检查；部署后检查实际 Pages URL |
| 性能、容量或大世界 | 相关功能先验证，再用独立工具串行测量并记录完整负载；测量不混入单元测试 |
| 仅 CI 编排 | 工作流语法、依赖、条件及脚本入口；不机械重跑完整游戏回归 |

当前使用标准 `dotnet test`，用例与最小夹具见 [单元测试说明](../tests/README.md)。测试合计应明显低于 **10 秒**，含发现、运行器与进程启动，不含构建／还原；不按耗时判失败。

单元测试不覆盖真实控件、浏览器及完整自主演化；桌面构建不能替代 WASM 裁剪发布。实际鼠标、键盘、触屏及导入导出须另行核对，触屏手势同时确认镜头变化与世界不变，输入法须真机验证。失败先定位行为，不删需求或扩大误差过关。

CI 范围见 [部署指南](deployment.md#发布到-github-pages)。验证与测量结果在任务回复中说明实际源码、环境和未覆盖范围；测量另注明种子、规模、配置、预热与复测，原生结果不能换算为浏览器帧率。日志、TRX、截图和测量数据放入已忽略的 `artifacts/` 或 Actions 产物。

核心模拟基准使用 `DOTNET_TieredCompilation=1 DOTNET_TieredPGO=1 dotnet run --project tools/SeWZC.WorldBox.Benchmarks -c Release -- artifacts/immutable-benchmark.json`。工具在计时外构建初态、至少预热 128 日并保存，记录各轮均值、逐日耗时、P95、峰值、分配量、GC、实际程序集哈希、规则和环境配额，并检查重复模拟和中途恢复后的结果。原生桌面及基准入口启用服务器 GC、分层编译和动态 PGO，基准记录实际 GC 模式和编译开关；可用 `DOTNET_gcServer=0` 对比工作站 GC、`DOTNET_TieredCompilation=0` 对比关闭分层编译的结果。平均耗时目标与逐日 P95、峰值分别报告，不将平均值当作单日硬上限。追加 `--default-rules` 测量默认规则；`--large` 只测 256²／4096 人，`--steady` 在计时外推进 12 日后测量后续 64 日；`--seed=整数` 与 `--start-day=整数` 可更换种子和计时起始日；`--years=100` 测量 12,000 日并记录逐年 P95，长期模式默认复测三轮；`--repetitions=整数` 可调整轮数。搭配 `--large --default-rules --years=100 --population-floor=4096` 会在每日计时外通过正常居民生成入口补足人口，并记录补充数量与实际人口，防止人口下降掩盖负载。追加 `--save-final` 在计时外按场景名和轮次分别保存终态，便于采样同一成熟世界；Linux 采集全进程 CPU，其他平台的 CPU 字段为 `null`；分配量覆盖全部托管线程，包含并行身体计算。追加 `--verify` 独立验证两个种子、两种地图在默认规则下运行 240 日及中途恢复的结果。

## 协作与文档维护

多人协作先分配文件责任；共享工作区的构建、发布、浏览器验收与测量由一个协调者串行安排。发布脚本重建 `artifacts/browser` 和 `artifacts/site`，源码稳定后再发布，不同时测试同一输出；需要稳定预览时复制到独立目录，共用 `obj` 的构建也不能竞争。

新增文档文件（含计划、报告、验证与决策记录）前，必须先说明文件路径、拟写内容、用途，以及为何不能在已有文档中简短说明，并取得用户明确同意；未获同意不得创建。用户已明确要求新增的具体文档视为该文件的授权，其他任务不推定授权。

按 [文档职责](README.md) 就地更新必要内容，优先改写现有段落或条目，沿用标题层级、排版与措辞；确需新增章节时按原有格式简短补充。文档和注释的篇幅应与改动规模相称，小功能或普通修复不堆叠章节、不扩写多份文档、不重复解释代码，不追加开发轮次、临时计划、验证报告或完整聊天。重要取舍只在相关决策条目中简短修订；历史原文用 Git 查阅。推送或部署授权沿用用户会话，不要求重复确认。
