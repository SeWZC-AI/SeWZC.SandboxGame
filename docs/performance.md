## 结论

标准 2,000 初始居民场景中，居民行为约占模拟时间的 **53%**，本地通信约占 **23%**；它们产生约 **83%** 的托管分配，是优先调查的路径。8,000 初始居民时两者占比增至约 87%。战争更新占标准场景约 6%，全图总量刷新约 5%，均有优化空间，但不是当前首要热点。

每 tick 分配量约 **2.91 MiB**。600 个测量 tick 内，各轮每 120 tick 发生 21–23 次 Gen 0、2–4 次 Gen 1、0–1 次 Gen 2 回收。这说明短命对象压力值得处理；这些数据没有把每个慢 tick 与具体 GC 暂停对应起来，不能将所有尾延迟归因于 GC。

原生 2,000 居民短程运行约 4.29 ms/tick；同一初始世界推进至 tick 600 后再测，人口到 tick 720 增至 4,184，约 15.72 ms/tick。8,000 初始居民约 23.59 ms/tick。当前 [UI 调度](../src/SeWZC.WorldBox.UI/MainView.cs) 在 `Step()` 返回后才检查 12 ms 预算，所以单步超过预算时仍会占用整个调用时长。原生结果不能换算为 WebAssembly 帧率。

## 环境与负载

- Debian 13、Linux 6.18.44、x64、AMD EPYC 9V74；容器 CPU 配额 4 核、内存上限 16 GiB。独立串行负载仍可能受到云主机调度影响。
- .NET SDK 10.0.401、运行时 .NET 10.0.12、Release、工作站 GC；保持默认分层 JIT，不额外禁用或调整 GC。
- 种子 451、256×256、平坦草地、16 个初始国家、资源充足、自然灾害关闭；标准场景固定 8 场战争，与原有 `--benchmark` 相同。
- 先用独立世界执行预热路径，再为每轮重新生成同样世界。默认每轮推进 60 tick，测量 tick 61–180，共 5 轮。生成、预热、保存、哈希和导入均在计时区域之外。
- 每 tick 单独计时并记录当前线程分配、每轮 GC 次数、终态人口、记忆数、实际导出的 UTF-8 字节数和存档 SHA-256。同一配置各轮终态哈希一致。

## 优化优先级

以下是调查时依据测量和代码提出的候选，当时尚未实施。后续实际落地的范围与收益见文末复测，不把候选中的所有事项视为已完成。

1. **居民行为与知识处理。** [行为更新](../src/SeWZC.WorldBox.Core/WorldEngine.Agents.cs) 每次目标评估构造候选列表，多次过滤/排序记忆，并在半径 6 内寻找资源；[环境观察与记忆](../src/SeWZC.WorldBox.Core/WorldEngine.Communication.cs) 构造信息后又复制，接收方也可能在去重拒收前构造副本。先细分目标选择、观察、劳动与移动，减少确定没有用途的临时对象；可使用保持顺序的单遍选择代替仅取首项的排序。必须保持平分规则、ID 分配、原始来源和观察时序，不能直接复用可变事实对象造成居民之间共享认知。
2. **通信的索引、邻居集合与报告去重。** `UpdateLocalCommunication` 每 tick 重建居民 ID 字典及位置 `GroupBy`/数组；每次交谈又生成并排序邻居数组和事实列表，消息逐个 `Remove`。`ReceiveSocietyReport` 对最多 2,048 条报告线性 `Any` 去重。可评估复用容器、按递送时间管理消息、按聚落/ID/位置和 `(RecipientSettlementId, FactId)` 建索引。索引需要在实际移动、死亡、转移、编辑和导入时可靠更新，并保持交谈对象按 ID 的稳定顺序，以及新获知信息下一 tick 才能转述。
3. **索引重建及全图聚合。** [引擎索引与统计](../src/SeWZC.WorldBox.Core/WorldEngine.cs) 每 tick 三次重建居民聚落列表，`RefreshTotals` 每 tick 扫描全部 65,536 地格。可评估复用居民列表、按拓扑变更刷新、增量维护领土统计；这是次级成本，必须覆盖拓荒、占领、领土笔刷、国家拆分与死亡等更新入口。
4. **长程演化与慢 tick。** 在保持功能和存档确定续演的前提下，复验 tick 120 等周期峰值、更多人口及真实浏览器。当前预算检查无法限制一个完整 `Step()` 的延迟；若需要分段调度，必须先定义事务边界，防止界面、保存或输入看到半个世界 tick。

`WorldEngine.Warfare.cs` 中的全图 BFS `FindPath` 当前只有定义，没有调用；实际军队经过 `MoveArmy` 使用 `MoveAgentTowards`。不能因 BFS 看起来昂贵就把它列为已测热点。

## 2026-10-02 热点优化复测

基于同一提交及前述测量入口优化了 [居民行为](../src/SeWZC.WorldBox.Core/WorldEngine.Agents.cs) 与 [通信](../src/SeWZC.WorldBox.Core/WorldEngine.Communication.cs)。生产改动仍在工作区，核心 `.cs` 源文件按文件名排序、以 `文件名 + NUL + 内容 + NUL` 拼接的 SHA-256 为 `66dc6eb9c0e0bb3b831d36cfa86c4158d2b56cee590b7e8d4d1dbf2a56050b1f`。环境、SDK、运行时、GC、种子和负载参数沿用上述配置；对照数据使用本轮保留的原版构建重新测量。

实际改动：

- 目标候选改为值类型并复用候选容器；最新知识、目标选择和记忆淘汰用保持平分顺序的单遍查找。聚落公开知识与递送事实选取保留同优先级、同时间时的原始顺序，减少完整排序与临时集合。
- 半径六的资源候选按距离检查。合法肥力最多 100，当前资源产出最多 1，因此评分上界为 `8 - 距离`；只在后续候选不可能达到当前最佳分数时停止。同分仍选原始行顺序中最早的地格，不扩大可见范围，也不使用未观察的远处资源。未来提高产出或肥力上限时应同步更新此上界。
- 通信 ID 字典、邻居容器和地格链表数组复用，每个通信阶段根据实时居民与位置重建；阶段结束释放临时居民引用。对 256×256 地图，地格头与人口链表数组合计约 296 KiB，为有界的常驻缓冲，不是每 tick 的新分配。
- 到期消息按原队列顺序取出，未来消息一次稳定压缩；避免逐条移除时反复搬移数组。交谈对象仍按 ID 排序，消息仍下一 tick 才能转述。新建观察与已经复制的递送快照直接交给记忆，保留共享证据和跨居民快照的独立复制。

实际存档字节数也完全一致。因此较大世界超过 32 MiB 的载荷边界仍存在；本次优化改善模拟执行与临时分配，没有改变保存格式或增加可保存规模的承诺。浏览器与真机耗时尚未复测，原生增益不能直接换算为浏览器 FPS。

原始对照记录位于 `artifacts/performance/optimization/before-*.json`、`after-*.json` 和汇总 `comparison.json`。复现仍使用前述 `--profile-simulation` 命令；比较代码版本时先保留原版构建，再串行运行相同参数，核对耗时、分配及终态哈希。

后续优化方向尚未实施，取舍如下：

- **保持模拟行为：** 优先验证建筑与居民查询索引、稳定选取替代完整排序、索引和清理集合复用。全图领土统计可考虑只在领土变化时刷新，但必须覆盖征服、地格编辑、聚落删除及导入等所有入口。用功能场景、中途保存续演及相同负载终态哈希验证；收益须重新测量。
- **降低思考、观察或交谈频率：** 当前普通决策约每 6 tick 复查、常规观察每 8 tick、普通交谈每 12 tick。放宽间隔可能减少工作量，但会改变居民反应、消息传播、文化交流和长期世界演化；紧急状态与玩家指令也需要分别定义。
- **优先减少慢 tick：** 先继续定位逐 tick 峰值，再考虑错开生育、领土和政策任务。已保存的未插桩复测中，60 的倍数 tick 平均约 8.43 / 32.51 / 20.30 ms，其余 tick 约 3.04 / 15.59 / 9.53 ms；其他 tick 也有峰值，周期任务不是唯一原因。错开任务会改变事件发生时点及后续演化，单纯降低平均耗时也不能保证每步落在界面 12 ms 预算内。

本轮两种探针的所有测量终态哈希均与优化后未插桩构建一致。没有重跑生产功能套件，沿用上节同一核心源码已通过的 29/29 结果。原始记录为 `artifacts/performance/remaining/stages-*.json` 与 `details-*.json`；细分探针构造脚本保存在同目录 `add-method-probes.py`。以上仍仅测原生模拟，浏览器、渲染及存储耗时未包含。
