## 来源与冲突处理

- **产品约定**来自已确认需求；**工程选择**说明当前用途与代价；**当前实现**须能对照代码；**未来方向**不等于交付承诺。代码、注释或测试不能反推成用户要求。
- 新的明确用户决定可以替代旧约定。发现文档与实现不一致时核对需求，在本次范围内修正并说明偏差；历史记录不阻止新需求。新增文档须事先说明内容和必要性并取得用户同意，维护规则见 [开发约定](development.md#协作与文档维护)。
- 同一事实只设一个维护位置，其他页面链接过去。SDK、依赖、版本、研究图、配方及数值以对应配置和规则文件为实现依据，避免复制整套清单。
- 产品与架构只写当前状态，不按轮次追加版本故事。决策在同一份记录中保留来源和替代链接；完整旧正文通过 Git 查阅。普通修复不新增决策文件。
- 验证结果在任务回复中说明实际提交或源码摘要、环境和未覆盖范围，不将旧结果归给新源码。日志、截图、JSON 与存档放入已忽略的 `artifacts/` 或 Actions 产物，不保存聊天、临时计划与无归属结论。
