# 项目文档入口

这里保存 SeWZC.WorldBox 的产品约定、设计原因、开发规则和验证证据，让后续开发者及 AI 能接续工作。先按任务选读；不要求每次把全部文档放入上下文。

## 按任务阅读

| 要做的事 | 先读 | 然后定位 |
| --- | --- | --- |
| 运行游戏、了解操作或发布 | [项目 README](../README.md) | [验证记录](verification.md) 中的复现命令 |
| 新增或调整产品行为 | [产品约定](product.md) | [设计决策索引](decisions/README.md)、相关代码与测试 |
| 修改模拟、存档或界面 | [开发约定](development.md) | [架构说明](architecture.md)、对应设计决策 |
| 排查 CI、存档或浏览器问题 | [开发约定的验证规则](development.md#按改动选择验证) | [验证记录](verification.md)、失败构建的日志与产物 |
| 了解某个限制为什么存在 | [设计决策索引](decisions/README.md) | 决策中的来源、代价、重新评估条件和证据 |
| 回看第二轮问答范围 | [第二轮范围](iteration-2-spec.md) | 这是历史输入；当前能力以产品文档和代码核对 |

仓库根部 [AGENTS.md](../AGENTS.md) 是 AI 自动发现入口，详细说明以本目录为主。

## 各类信息放在哪里

| 文档 | 负责回答 | 何时更新 |
| --- | --- | --- |
| `product.md` | 玩家能做什么、行为应怎样、哪些尚未实现 | 产品行为、范围或验收场景变化 |
| `architecture.md` | 状态属于谁、模块如何协作、当前技术边界 | 数据流、依赖或平台适配变化 |
| `development.md` | 如何修改、定位与验证，哪些错误要避免 | 开发流程或工程约定变化 |
| `decisions/` | 为什么选择这样做、有什么代价、何时值得改 | 影响多个模块或长期行为的取舍变化 |
| `verification.md` | 哪次构建在哪种环境通过了什么 | 实际完成新的检查并获得证据之后 |
| `iteration-2-spec.md` | 第二轮交互问答当时确认了什么 | 仅修正记录错误；后续变化写现行文档和新决策 |

## 保持文档可信

- **确认的产品约定**来自用户需求与问答；**工程选择**来自实现取舍；**当前实现**描述代码现状；**未来方向**不等于已承诺交付。写清来源，避免相互混用。
- 文档描述意图，代码与可复现测试证明实际行为。发现不一致时明确指出偏差，并在本次任务范围内修正；不能因为已有代码如此就反推为用户需求。
- 新的明确用户决定可以替代旧约定。同步更新受影响的产品、决策和验收，保留原因；本目录不增加额外的逐项审批流程。
- 同一事实尽量有一个主要维护位置，其余文档用链接。SDK、依赖和数值以相应配置或代码为准，不在多处复制整套列表。
- 记录能帮助下一次修改的结论、原因与验证，不保存完整聊天、模型思考过程、凭据、临时机器路径或没有状态的待办清单。

本次整理以 `ba395b9` 的实现及此前确认的第二轮需求为基线；之后修改功能时应随代码维护现行文档。历史测试结果不能自动证明后续提交。
