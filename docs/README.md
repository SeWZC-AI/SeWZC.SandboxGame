## 来源与冲突处理

- 产品约定注明已确认需求，工程选择说明用途与代价，当前实现对照代码。约束依据见 [开发约定](development.md#约束必须有现行依据)。
- 文档与实现冲突时核对现行需求，在本次范围内修正；新的明确用户决定可替代旧约定。
- 同一事实只设一个维护位置，其他页面链接过去。SDK、依赖、版本、研究图、配方及数值以对应配置和规则文件为实现依据，避免复制整套清单。
- 产品与架构只写当前状态，不按轮次追加版本故事。决策在同一份记录中保留来源和替代链接；完整旧正文通过 Git 查阅。普通修复不新增决策文件。
- 文档与注释的维护规则见 [开发约定](development.md#协作与文档维护)。
