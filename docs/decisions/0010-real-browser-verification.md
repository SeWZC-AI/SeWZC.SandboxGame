# ADR-0010：真实浏览器输入、只读测试快照与部署后验证

- 状态：采用
- 记录日期：2026-10-01
- 来源：Pages 可部署、交互稳定与实际验收的需求；测试桥和分层检查是工程选择。

## 背景

Avalonia 在 canvas 内绘制，普通 DOM 选择器不能定位内部按钮。核心测试和静态文件检查无法证明裁剪后的应用启动、输入、存储或 Pages 子路径正常。

## 决定与约束

仅显式 `?e2e=1` 开启只读语义快照，供自动化定位真实控件。通过真实鼠标、键盘、触屏和文件选择执行行为，再检查实际 IndexedDB 或导出文件；不提供直接编辑世界、推进时间的测试命令。

发布后先验证本地仓库子路径，alpha 部署后再对实际站点运行桌面、触屏和运动检查。普通入口不暴露测试快照。软件回退只允许精确匹配的已知诊断，并检查实际游戏画布像素；其他控制台与页面错误仍然失败。

## 原因与代价

直接调用核心命令速度更快，适合验证规则，却绕过了玩家输入、界面与存储；单靠截图也无法证明世界实际变化。分层检查成本更高，浏览器有环境噪声，语义桥须随真实控件维护，但能发现错误路径、空白画面和假成功。

## 重新评估条件

更换渲染后端、自动化工具或部署平台时可以调整测试设施；保留真实输入和真实状态验证。性能测量需独立负载，不能用共享机器上的资源竞争推断游戏退化。
