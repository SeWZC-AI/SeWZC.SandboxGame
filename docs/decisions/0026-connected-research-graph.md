# 0026：有真实依赖连线的科技树

状态：节点图采用；全树混排、外围长连接与默认祖先高亮被 [0027](0027-readable-research-branches.md) 替代。日期：2026-10-04。来源：用户在首轮交付后强调「科技『树』」，要求明确的枝干关系。这替代 [0025](0025-research-trees-and-empire-simulation.md) 中按分支换行的卡片呈现；研究、实物生产和已交付存档继续沿用原规则。

## 决定

科技树使用实际节点与有箭头的连接线展示完整有向无环图。节点按依赖深度排列，允许多个起点、分叉和汇合；每个实际前置关系都有一条连接，跨层依赖沿节点区域外侧走线，不能穿过其他节点。选中研究高亮其递归前置路径。

用直接按钮切换全树／科技／魔法视野。树形位置不随设备宽度变成列表；鼠标与触屏都支持拖动，缩放按比例改变节点和连接的几何。全树概览、定位所选和帝国终点方便在手机上导航。桌面展开时将原地图区域让给科技树，恢复后回到地图与详情并列。

## 原因与边界

分组卡片能列出前置名称，但不能直观看出研究的分叉与汇合。布局与连接只读取 `ResearchRules`，不添加虚构依赖，不替居民授予知识，也不改变世界或随机状态。周期刷新只更新节点状态、样式和连接，保留滚动与缩放。

全树概览在小屏幕上会缩小文字，用户可放大并拖动查看；这比删去枝干更符合树形观察。当前采用分层布局与外侧长连接，节点数量显著增加时可重新评估交叉较少的图布局；测试继续约束连接完整、节点不重叠、线路不穿过节点及查看不修改存档。

## 实现与验证

`ResearchTreeLayout` 负责节点与每条依赖的几何，`ResearchGraphControl` 负责连接绘制、拖动、缩放与定位，`MainView.Research` 负责城镇研究状态和立项。Headless 检查全部实际依赖与线路安全；浏览器从交付的双帝国存档验证桌面／触屏输入、终点状态与观察不变性。实际结果另记于 [验证记录](../verification.md)。
