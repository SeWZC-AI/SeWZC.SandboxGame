# ADR-0013：科技与魔法并行发展，保持各自的生产基础

- 状态：采用，扩展 [0011](0011-evolution-and-map-tools.md) 的文明发展范围。
- 日期：2026-10-02。
- 来源：用户通过同步问答选择“近现代与未来”和“科技与魔法并行”，并明确两者不互斥，但应避免过度融合。具体研究、配方、成本与阶段名称为本轮工程选择。

## 决定

科技线以工业冶炼、电气化、自动化农业、先进计算与制造推进；魔法线以晶体凝炼、符文生产、高阶以太工艺推进。两条路线允许同城并存，各自的高级研究不以另一条路线为前置。科技设施不用魔晶，魔法设施不用合金或动力单元；两者可共享粮食、木材、石材和矿石等普通资源。

动力单元表示可以装载和搬运的实体能源载体，本轮没有跨地区电网。新设施按配方使用工人随身原料，产物仍归工人携带，抵达家园才入库。魔法生产另消耗实际施作者的魔力并检查天赋与训练。首批产出记录世界事件与实际参与者，后续用持久化批次数观察产能。

当地研究与生产设施决定可用能力。现有 1–5 级国家古代发展参数保留原用途，不按新增研究数无限提高军事和基础采集倍率。高级知识可以实际传播，但不会顺带补造前置知识；缺少运营前置的设施不能生产。关闭新魔法发展阻止新的魔法研究、设施与训练，保留已完成成果和已开始项目。

新增合金、动力单元、魔晶和生产批次数进入格式 6，字段必须显式保存并校验，拒绝格式 5 及更早版本。原料途中、加工后返乡途中以及高阶研究完成后的续演保持确定性。

## 边界与验证

这批交付的是到未来制造／以太文明的生产与研究基础路径，不包含现代军种、铁路、电网、星际探索或科技魔法融合。扩展这些系统时仍须落实位置、资源和已知信息约束。

主要实现见 `AdvancementRules.cs`、`WorldEngine.Advancement.cs`；机制场景见 `AdvancementTests.cs`，共享界面和实际浏览器场景分别在 UI 测试与 `tests/browser/advancement.cjs`。实际运行证据见 [验证记录](../verification.md)。配方平衡、默认世界的发展节奏及大规模工人运输需要继续以测量结果调整。

本轮后续由 [ADR-0014](0014-land-and-transport.md) 加入航空、阶段矿藏与格式 7，并将无线信号放到电气化之后；上文保留格式 6 首次引入时的归属。当前配方与前置以 [产品约定](../product.md) 为准。
